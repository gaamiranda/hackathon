3. The deterministic engine

All money is Decimal, quantised to two places at each step (engine/costing.py):

subtotal      = quantity × unit_price          (quantity = the buyer's request, not the quoted one)
discount      = subtotal × discount_pct
pre_tax_total = subtotal − discount + shipping
tax           = pre_tax_total × tax_rate       (buyer-side, from config)
landed_cost   = pre_tax_total + tax
math_ok       = |pre_tax_total(at quoted qty) − document_stated_total| ≤ 0.01

Checks per quote: MOQ, lead time against the delivery window, budget, capacity, blacklist, defect threshold, and the math check. A failed math check stops the workflow (CALC_MISMATCH) until a human confirms the computed figure; the original stated total is kept in the audit log.

Scoring (engine/scoring.py), over eligible quotes only: price and lead time are min-max normalised (best = 100); reliability = ½·on-time% + ½·(1 − defect rate)%; risk = 1 − risk_score where risk_score = ½·min(defect/max_defect, 1) + ½·min((1 − on-time)/0.2, 1), amplified by capacity utilisation above 80%. Weighted sum with configured weights (0.30 price, 0.20 lead time, 0.30 reliability, 0.20 risk) gives a 0–100 total; the breakdown sums to the total. Negotiated offers replace unit price and lead time for costing while the originals stay for audit.

4. Workflow, gates and events

CREATED → EXTRACTING → [NEEDS_HUMAN_EXTRACTION] → EXTRACTED → VALIDATING → [CALC_MISMATCH]
  → ENRICHING → SCORING → RECOMMENDED
  → NEGOTIATION_DRAFTED → AWAITING_NEGOTIATION_APPROVAL → NEGOTIATING → COUNTER_RECEIVED → RE_SCORING → RECOMMENDED
  → AWAITING_PO_APPROVAL → PO_GENERATED (terminal)
interrupt (quantity / budget / date) from RECOMMENDED, EXTRACTED, AWAITING_* → REPLANNING → VALIDATING …

Four human gates: the extraction form (missing or unsupported fields), the math check, negotiation approval (the human may edit the draft; edits are re-filtered), and PO approval. PurchaseOrder is constructed in exactly one place, reachable only through the approval endpoint; no agent has a tool that can generate one.

Every transition and every agent call emits an append-only WorkflowEvent (seq, actor ∈ agent|engine|human|supplier, type, state before/after, payload). The frontend consumes it over Server-Sent Events with replay and reconnect; the "agent lanes" and "moment cards" of the War Room are derived purely from this stream. Runs and events are persisted to disk (atomic run.json + events.jsonl) and reloaded on startup; runs interrupted mid-transition are recovered to the nearest safe state with a run.recovered event.

5. The interrupt (replanning without restart)

An interrupt versions the request (previous versions kept), discards any pending negotiation draft (applying a counter already received), re-validates, re-enriches and re-scores the existing quotes with negotiated offers carried over, and produces a ReplanImpact: what changed, per-supplier eligibility, landed cost and score before and after, and the recommended supplier before and after. The Decision Agent explains the diff from the engine's diff lines. In the demo, 2,000 → 5,000 units makes Borealis ineligible on capacity and the recommendation moves to Cobalt in under a second. If nothing is eligible after a change, the run reaches RECOMMENDED with an escalation instead of failing.

6. LLM path, OpenClaw and fallbacks

Calls are single-shot JSON tasks: extract (one per document), explain, explain_diff, draft, negotiation_verdict. No conversation history is sent. Each call travels:

agent → ReplayCache → FallbackLLMClient( OpenClaw /v1/chat/completions on the box → organiser AWS LLM gateway ) → Claude Sonnet 4.5
  • OpenClaw (starter-kit install on Lightsail) exposes an OpenAI-compatible endpoint on loopback. A dedicated agent procureai has tools.profile: minimal plus an explicit deny list (exec, write, edit, process, web_fetch, browser, sessions, cron, memory, …), no bootstrap files and no memory, because untrusted supplier text passes through it. Verified: stateless between requests, refuses tool use, honours the system message. It adds 0.5–1.5 s per call.
  • Fallback: if OpenClaw is unreachable the same call goes to the gateway directly; the event records which route answered ("via OpenClaw" / "via gateway"). A per-task route pin exists as an emergency switch.
  • Replay cache: every live response is recorded under a hash of the prompt (committed to the repository). Tests run in replay-only mode and therefore assert the behaviour of the real model; demos replay or run live by rotating the cache.
  • Manual mode: when both routes are down, /health reports llm: down, the UI shows a red banner, every document routes to a manual extraction form (document text alongside the fields), and the engine produces identical numbers. A comparison matrix view contains no model text at all.

Gateway facts that shaped the design (docs/INFRA.md): ~3 s fixed latency per call, so one call per document and one per explanation; output silently truncated at 256 tokens unless num_predict is sent; the model wraps JSON in code fences despite instructions, so parsing is tolerant with one repair call.

8. Data

  • Synthetic quotations, generated deterministically with ground truth: scenario A (PDF table with a wrong total, two-formula spreadsheet, email with an injection line) and scenario B (two-sheet workbook, letter-style PDF, email with a P.S. injection, form PDF with transposed digits). Text per document under 3,000 characters.
  • Supplier history: read-only JSON store (seven suppliers, one blacklisted) behind a repository interface; supplier names map to ids through an alias table so an unknown supplier is ineligible rather than guessed.
  • Supplier personas: scripted counter-offers per supplier and round, one of which carries an injection sentence.
  • Caches: data/llm_cache/ and data/judge_cache/, committed; data/runs/ persisted runs on the box (gitignored).

10. Testing and failure drills

  • 313 backend tests (about 2 s, no network by construction): engine golden numbers hand-computed in the tests; contract tests against fixtures; extraction benchmark across all layouts against recorded live responses; policy and round-cap tests; number-guard tests including a real tripped sentence; persistence and recovery; full end-to-end mock runs for both scenarios through negotiation, interrupt and PO; prompt-stability tests across dates so cache keys do not drift.
  • Seven failure drills executed against the live box (docs/DRILLS.md): stop OpenClaw mid-run (fallback within one poll; a stale-banner defect found and fixed), gateway at a closed port (manual mode), backend restart mid-negotiation (gate intact, 1.9 s), corrupt and oversized uploads, instance reboot (all green in 49 s), interrupt with a draft pending, and the scripted on-stage break-it sequence.
  • Timings: a full run through the UI, upload to PO, under 90 seconds with cached model answers; 12–15 s of extraction and 5–8 s per explanation when live.

11. Known limitations

  • Document layouts: extraction is validated on seven synthetic layouts, not arbitrary real-world documents; unreadable documents fall back to the human form by design.
  • Single-product requests; multi-line orders are on the roadmap.
  • Supplier replies are simulated by scripted personas; a real mailbox would feed the same event and gate.
  • HTTP only on the deployment (no domain); the OpenClaw hop adds up to 1.5 s per call.
  • Relative (min-max) scoring means one supplier's improved offer can lower another's dimension score; documented and shown as "relative scoring".

12. How the project was run

A planning agent maintained PLAN.md as the single source of truth (architecture, contracts, 34 numbered decisions, status), and handed out one small, testable task at a time to coding agents with explicit acceptance criteria; every change was reviewed and committed by a human. The contracts were frozen on day one, every agent had a mock before it had a model, and the whole demo ran offline before any credential existed, which is why the live integration (gateway, OpenClaw, judge, deployment) slotted in without redesign.
